# Lesson 4: Test and maintain the handoff

Check whether another session can use the map, then repair what did not survive.

## Test the next session, not just the file

A context map is useful only if it helps the next task. A tidy file can still point to a deleted contract, omit the acceptance check, or contain conflicting instructions. Treat the handoff as something to try, not something its author can certify by appearance.

For the constructed export task, a reviewer who did not read the original chat should be able to find the current contract, name the access boundary, identify the requested change, and choose the relevant check from the handoff.

## Compare your work

Correct the maintained source when a rule changes, update affected pointers, and remove superseded copies through the normal review process. A passing handoff exercise establishes something about this handoff; it is not proof that every future agent will follow the rules.

## Retrieval check

What is the strongest completion statement for a handoff exercise?

1. The file is short, so every future agent will understand it.
2. The agent said it understood, so no check is needed.
3. The reviewer found the named contract and acceptance check; the remaining gaps and limits are recorded.
4. All context-management problems are solved for the project.

<details>
<summary>Check your answer</summary>

Answer: 3. The third statement names observations and their limits. File length and confidence do not establish successful transfer, and one exercise does not prove future compliance.
